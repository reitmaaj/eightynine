# Testing: evaluator core (control flow)

*BDD scenarios for the interpreter milestone, Phase A (value/instance core
and control-flow evaluator). Mirrors the reference interpreter's `eval.ml`
for the covered instruction subset.*

## EVAL-001 Runtime value model

SCENARIO: Num versus ref discrimination
GIVEN a constructed runtime value
WHEN its `is_ref` discriminator is read
THEN a numeric value reports 0 and a reference value reports 1.

SCENARIO: Reference kinds
GIVEN reference values built as null, func, extern and exn refs
WHEN their `kind` is read
THEN the four kinds are pairwise distinct and null is the only kind
    reported by `w89_ref_is_null`.

SCENARIO: Exn reference payload
GIVEN an exn ref built from a tag instance and an argument list
WHEN the reference is unwrapped
THEN the payload holds exactly the same tag instance and the same
    argument values in the same order.

## EVAL-002 Tag instance identity

SCENARIO: Identity of tag instances
GIVEN two freshly allocated tag instances
WHEN they are compared for identity
THEN they are not the same instance.
GIVEN one tag instance compared against itself
THEN it is the same instance.
GIVEN a tag instance shared through a module instance's import
THEN the import resolves to the same instance (pointer-identical),
    which is the basis for `catch` matching in Phase D.

## EVAL-003 Const and nop

SCENARIO: Constants
GIVEN a program consisting of a single `i32.const`/`i64.const`/
    `f32.const`/`f64.const`
WHEN evaluated
THEN the constant is the single result value.
GIVEN an empty program
WHEN evaluated
THEN evaluation succeeds with no results.

SCENARIO: Nop
GIVEN a program `nop`
WHEN evaluated
THEN the stack is unchanged.

## EVAL-004 Locals

SCENARIO: Local set/get/tee
GIVEN a frame whose local 0 holds a value and a program
    `local.get 0`
WHEN evaluated
THEN the local's value is the result.
GIVEN a program `i32.const 9, local.set 0, local.get 0`
WHEN evaluated
THEN the result is 9 and local 0 now holds 9.
GIVEN a program `i32.const 9, local.tee 0`
WHEN evaluated
THEN the result is 9 and local 0 holds 9.

SCENARIO: Uninitialized local
GIVEN a frame whose local 1 is unset and a program `local.get 1`
WHEN evaluated
THEN evaluation crashes with "read of uninitialized local".

## EVAL-005 Globals

SCENARIO: Global get/set
GIVEN a module instance with a mutable global holding 5 and a program
    `global.get 0`
WHEN evaluated
THEN the result is 5.
GIVEN a program `i32.const 7, global.set 0, global.get 0`
WHEN evaluated
THEN the result is 7 and the global now holds 7.

SCENARIO: Immutable global
GIVEN a module instance with an immutable global and a program
    `i32.const 1, global.set 0`
WHEN evaluated
THEN evaluation crashes with "write to immutable global".

## EVAL-006 Drop and select

SCENARIO: Drop
GIVEN a program `i32.const 1, i32.const 2, drop`
WHEN evaluated
THEN the stack holds a single value 1.

SCENARIO: Select
GIVEN a program pushing two candidate values and a condition
WHEN a `select` is evaluated
THEN a zero condition keeps the first candidate and a nonzero condition
    keeps the second.
GIVEN a typed `select_t` with the same operand shapes
THEN it behaves identically.

SCENARIO: Stack underflow
GIVEN a program `drop` on an empty stack
WHEN evaluated
THEN evaluation crashes with "stack underflow".

## EVAL-007 Blocks

SCENARIO: Block result
GIVEN a program `block (result i32) i32.const 7 end`
WHEN evaluated
THEN the result is 7.

SCENARIO: Block with parameters
GIVEN a block whose blocktype is a function type with parameters, fed
    the right number of argument values
WHEN evaluated
THEN the arguments become the block's inputs and the body result is
    produced.

SCENARIO: If
GIVEN a program `i32.const c, if (result i32) <then> else <else> end`
WHEN evaluated
THEN a nonzero c executes the then-branch and zero executes the
    else-branch (or the empty else).
GIVEN an `if` without else
THEN a zero condition leaves no result.

## EVAL-008 Branches

SCENARIO: br and br_if
GIVEN a program `block (result i32) i32.const 9, br 0 end`
WHEN evaluated
THEN the result is 9 (the branch target arity is honored).
GIVEN a `br_if` with a zero condition
THEN it does not branch and the body continues.
GIVEN a `br_if` with a nonzero condition
THEN it branches to the label.

SCENARIO: br_table
GIVEN a `br_table` with a selector equal to a listed label
WHEN evaluated
THEN control transfers to that label.
GIVEN a `br_table` with a selector at or beyond the list length
THEN control transfers to the default label.

SCENARIO: Nested labels
GIVEN an inner block branching to an outer label (`br 1`)
WHEN evaluated
THEN control transfers to the outer label and intermediate blocks are
    unwound.

SCENARIO: Loop re-entry
GIVEN a loop that counts down with `br 0`
WHEN evaluated
THEN the loop body re-enters until the break condition fails and the
    final result is produced.

## EVAL-009 Return and unreachable

SCENARIO: Return
GIVEN a program `block i32.const 3, return, unreachable end` without an
    enclosing frame (Phase A unit tests have no calls yet)
WHEN evaluated
THEN `return` unwinds the enclosing labels and delivers its carried
    values to the enclosing frame, and because no frame exists yet
    evaluation ends in the reference's "undefined frame" crash — with
    the trailing body (here `unreachable`) never evaluated.
GIVEN a bare `return` at the top level
THEN evaluation crashes with "undefined frame".

SCENARIO: Unreachable
GIVEN a program containing `unreachable`
WHEN evaluated
THEN evaluation traps with "unreachable executed".
GIVEN code after an unreachable instruction (stack-polymorphic context)
THEN the trap fires before the trailing instructions execute.

## EVAL-010 Numeric traps

SCENARIO: Divide by zero
GIVEN an `i32.div_u`/`i32.div_s`/`i64.div_u`/`i64.div_s` with divisor 0
WHEN evaluated
THEN evaluation traps with "integer divide by zero".
GIVEN an `i32.rem_s` with divisor 0
THEN evaluation traps with "integer divide by zero".

SCENARIO: Signed overflow
GIVEN an `i32.div_s` of INT_MIN by -1 (or i64 equivalents)
WHEN evaluated
THEN evaluation traps with "integer overflow".
GIVEN an `i32.rem_s` of INT_MIN by -1
THEN evaluation succeeds with result 0.

SCENARIO: Invalid conversion
GIVEN an integer truncation of a NaN, infinity, or out-of-range float
WHEN evaluated
THEN evaluation traps with "invalid conversion to integer".

## EVAL-011 Numeric results

SCENARIO: Arithmetic and comparisons
GIVEN representative i32/i64/f32/f64 unary, binary, test and comparison
    programs
WHEN evaluated
THEN the results match the numeric library and the float bit patterns
    are preserved exactly.

## EVAL-012 Terminal instructions

SCENARIO: Jumping instructions escape labels
GIVEN a `br`, `return`, trap or (later) throw produced inside a block
WHEN the label is unwound
THEN the jump propagates out of the label and the label's pending body is
    discarded, not stepped.
GIVEN a `br` whose depth exceeds every enclosing label
WHEN evaluated
THEN evaluation crashes with "undefined label".
GIVEN a `return` outside any frame
WHEN evaluated
THEN evaluation crashes with "undefined frame".
