# Design: SIMD (fixed-width v128, then relaxed)

*Drives `.agent/testing+acceptance/0025..0029-simd-*.md` (PLAN S3.1).
Adds the v128 runtime value and the SIMD (fixed, then relaxed) instruction
set to decoder → validator → evaluator, with conformance and differential
coverage. Concept: `.agent/concept/0000-concept.md`. Stories: `0000`. No
decoder/validator type-level change to the value-type tag (`v128` byte
`0x7B` already decodes); the work is the 128-bit runtime payload, the `0xFD`
decode prefix, per-lane kernels, and the deterministic float profile.*

## 1. Current state and gap

- `v128` is already a valtype (`W89_T_V128=0x7B`, `module.h:8`) and
  `read_valtype`/`fmt_valtype` handle it, but no instruction produces or
  consumes it; SIMD modules decode-reject at `decoder.c:2694` and are
  counted as conformance *skips*.
- The runtime value `w89_value` (`eval.h:61-67`) is a 64-bit union and
  cannot hold 128 bits; a wide payload must be added without disturbing
  scalar numerics.
- SIMD `.wast` is already vendored (59 flat `simd_*.wast` at the top of
  `vendor/testsuite-main`); no separate `simd/` dir.
- Differential harness has no SIMD engine flag or NaN rule yet.

## 2. Runtime value: a 128-bit member

Extend `w89_value` with a 128-bit carrier (lane struct or wide member) used
only when the operand is typed v128; scalars keep the 64-bit fast path. All
value construction/splice/save sites (`w89_code.vs`, unified `c->vs`,
`w89_local`, `w89_globalinst.value`) must copy the full value so a v128
never aliases or truncates a scalar. A v128 MUST remain a distinct operand
type: the validator already types v128 as a non-ref `vt`; scalar opcodes
must keep rejecting it and SIMD opcodes must keep rejecting scalars.

> **Status (B1, LANDED on `main`).** The core widening landed as a
> single direct change: a `w89_v128` (16-byte byte carrier) union member in
> `w89_value` (`eval.h`), a constructor `w89_value_v128`, and the `w89_v128`
> type in `module.h`. Every `w89_value` is now a full 16-byte element on the
> unified value stack, so by-value splice/save is a whole-struct copy; no
> site truncates a vector to a scalar and scalars keep the `u.num` fast path.
> Proven by the scalar suite staying green, a v128 round-trip unit test, and
> 37171/0 conformance / 3888/0 differential.
>
> The `0xFD` decode/validate/eval enablement of `v128.const`/`load`/`store`
> is **B1-b, LANDED on `main`** together with making v128 a first-class value
> type so the sweep stays green. `simd_linking.wast` (v128 global
> const-expr/imports) and `simd_const.wast` now run their module-validation
> commands as real assertions (simd_const 373 passed / 385 skipped,
> simd_linking 3 passed). Full sweep 37460 passed / 0 failed / 0 STALL.
> The ~385 `simd_const` skips are the `assert_return (invoke ...) (v128.const
> ...)` value commands: they need driver-side v128 result/arg marshalling,
> which is a separate following increment (B1-c). Global const-expr `v128.const`
> flows through the iterative driver via `eval_expr_driver`; no lane arithmetic
> is needed. See `tmp/S31-simd-b1-status.md`.

## 3. Decoder (`0xFD`)

Replace the reject at `decoder.c:2694` with a sub-opcode dispatch following
the `0xFC` pattern (`in.sub`). Add a 16-byte lane-immediate field to
`w89_instr` (`module.h:133-152`) for `v128.const` and lane shapes;
`v128.load`/`store` and lane-granular loads reuse the memarg path. Invalid
sub-opcodes or lane shapes are "illegal opcode"/"unsupported feature" as
appropriate; a real SIMD module must no longer be a blanket skip.

## 4. Validator

Add SIMD cases to the instruction type switch (`validate.c:2141`); the
`apply_it` stack machinery (`:3562`) already applies ins/outs. Typing stays
at the `vt` level (v128) while the evaluator carries the 128-bit payload;
the only widening concern is that any SIMD op typed as producing multiple
results is not yet expressible in the single-result helper used by `0x1C`
(`validate.c:2180-2183`) — SIMD ops are single-v128 so this is not hit.

## 5. Evaluator: per-lane kernels

Route `0xFD` in `step_plain` (`eval.c:4661-4669`) to a new `step_simd`
family. Lane kernels live in a new SIMD lane library parallel to
`numeric.c` (numeric.h is purely scalar i32/i64/f32/f64). Integer lanes are
exact wrapping per lane; float lanes follow the deterministic NaN profile
shared with scalar f32/f64. Ops: integer/float arithmetic, compares,
shuffles/swizzle (swizzle OOB lane → 0; shuffle static OOB → reject),
splat/extract/replace, bitmask, dot/extmul, and the load/store-lane and
wider-load shapes.

## 6. Relaxed SIMD (deterministic profile)

Concept `0000:23-24` and story `0000:36` pin a deterministic float profile.
Each relaxed op selects one fixed, documented acceptable result recorded
here, reproducible across runs and builds (independent of host CPU flags,
scheduling, FP rounding). Relaxed float NaN lanes canonicalize like fixed
SIMD and scalars.

### Deterministic choice register
Filled as each relaxed op lands (op → fixed choice).

## 7. Conformance

Enable the SIMD subset sweep, then the full sweep, over the 59 vendored
files: zero FAIL/zero STALL, skips only for by-design exclusions (relaxed
lanes before the deterministic profile lands, non-core/thread features).
The driver must treat a now-implemented SIMD module as real assertions, not
decode skips.

## 8. Differential

Enable SIMD only after the interpreter runs it. Compare v128 exact-bits
lane-for-lane against wasmtime and wasm-interp with the SIMD engine flag;
SIMD NaN lanes extend the scalar NaN rule in `compare.py` (NaN≈NaN,
NaN-vs-finite FAIL). The generator must not emit SIMD until the engine
flags/rule are wired. Relaxed ops are differential only once both sides
share a deterministic rule. (wasmer remains an optional, absent 4th oracle.)

## 9. Out of scope / tracked exclusions

Text format parsing, threads/atomics, WASI, component model remain excluded.
Relaxed-SIMD features with no fixed acceptable rule are deferred until a
deterministic choice is defined.
