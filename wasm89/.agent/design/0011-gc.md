# Design: GC and deep function references

*Drives `.agent/testing+acceptance/0030..0033-*.md` (PLAN S3.2). Adds the
GC heap runtime (struct/array/i31 instances), the `0xFB` instruction
family, and deep/typed function references, with conformance (vendored
`gc/`) and differential coverage. Concept: `.agent/concept/0000-concept.md`.
Stories: `0000`. The type level is already present: recgroups, struct/array/
i31 declaration types, and the `anyref`/`eqref`/`structref`/`arrayref`/
`i31ref`/exn abstract-heaptype hierarchy decode and validate. What is missing
is the runtime heap, the `0xFB` prefix, and typed function-reference
tightening.*

## 1. Current state and gap

- Type machinery is done: `w89_absheaptype` (`module.h:15-28`), `w89_reftype`
  (`:30-35`), `w89_vt` (`:37-41`), packed/field/comp/subtype/rectype decls,
  and type-section decode/validate.
- Several reference ops already work end-to-end: `call_ref` (`eval.c:1891`),
  `ref.null`, `ref.is_null`, `ref.func` (untyped/typed index), `ref.eq`,
  `ref.as_non_null`, `br_on_null`/`br_on_non_null`.
- Missing: the `0xFB` instruction prefix (`struct/array/i31` construct/
  access, `ref.test`/`ref.cast` + null variants, typed `ref.func`
  annotation), the GC heap runtime, and a heap-object reference kind.
- `w89_ref` (`eval.h:46-53`) has kinds NULL/FUNC/EXTERN/EXN; GC needs a
  heap-instance kind (and an inline i31 carrier). `w89_store` (`:177-214`)
  has no GC arena.
- Full GC `.wast` is not vendored (only `binary-gc.wast`); the upstream
  `gc/` testsuite must be vendored into `vendor/testsuite-main`.

## 2. Runtime heap and reference model

- Add a heap-object reference kind and a store-owned arena of struct/array
  instances. i31 is represented inline as a 31-bit reference (not a heap
  allocation) so `i31.new`/`i31.get_s`/`i31.get_u` are cheap and
  `ref.eq` on equal i31 works by value.
- Instance identity is pointer identity on the arena; `ref.eq` is
  identity/equal-i31, never a field-value comparison.
- A struct field may be packed (i8/i16): store packed, sign/zero-extend on
  `get`; writes never bleed across byte boundaries.
- Extend the `w89_value`/`w89_ref` constructors and match helpers without
  disturbing existing reference behaviour.

## 3. Decoder (`0xFB`)

Replace the reject at `decoder.c:2687` with sub-opcode dispatch:
`struct.new/get/get_s/get_u/set`, `array.new/data/fixed/get/get_s/get_u/set/
len`, `i31.new/get_s/get_u`, `ref.eq` (exists), `ref.test`/`ref.cast` +
null variants, typed `ref.func`. Reuse existing type-index immediates;
invalid subs → "illegal opcode"/"unsupported feature".

## 4. Validator

Add GC cases to the type switch (`validate.c:2141`) using the existing type
and subtyping machinery (`apply_it` at `:3562` applies ins/outs). Enforce
the field-type rules (packed types only in struct/array), the reference
hierarchy (structref <: eqref <: anyref etc.), and cast target heaptypes.
Deep function-reference groups already validate; tighten typed `ref.func`/
`call_ref`/`br_on_null` typing.

## 5. Evaluator

Route `0xFB` in `step_plain` to a `step_gc` family. Heap ops allocate on the
store arena, read/write packed/unpacked fields, honour null/OOB traps, and
implement `ref.test`/`ref.cast` subtype checks against the runtime concrete
type. i31 ops are inline.

## 6. Function references (deep/typed) as GC prerequisite

Typed `ref.func`/`call_ref` verify the callee signature before invocation;
`ref.as_non_null`/`br_on_null` narrow to non-null. Recursion groups decode,
validate, and evaluate without false type mismatch.

## 7. Conformance

Vendor `vendor/testsuite-main/gc/` (upstream), then drive the GC subset and
full sweep: zero FAIL/zero STALL, skips only for by-design exclusions.
Previously non-GC suites must stay green.

## 8. Differential

Enable GC only after the interpreter runs it. Generated GC cases expose only
address-independent observables (ref identity via `ref.eq`/`ref.test`,
structural equality, booleans) and compare equal across wasm89, wasmtime,
and wasm-interp with the GC flag; raw addresses are never compared. GC traps
are rt≈rt interchangeable.

## 9. Out of scope / tracked exclusions

Text format parsing, threads/atomics, WASI, component model remain excluded.
extern.convert and non-core host conversions are out of scope unless later
tracked.
