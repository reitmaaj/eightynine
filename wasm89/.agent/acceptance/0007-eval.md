# Acceptance: evaluator core (control flow)

*Acceptance criteria for the interpreter milestone, Phase A. Reference:
WebAssembly Core Spec 3.0 chapter 4, and the reference interpreter's
`eval.ml` step/eval functions for the covered instruction subset.*

## MUST

* The runtime value model MUST distinguish numeric values from references
  (`is_ref`), and MUST represent four reference kinds: null, func, extern
  and exn. An exn reference MUST carry a tag instance and an argument
  value list.
* Tag instances MUST be compared by identity (pointer equality), not by
  type; this identity is the basis for exception catch matching.
* The evaluator MUST follow the reference's `config`/`step`/`eval`
  structure: a frame, a code deque (value stack + instruction deque), and
  a call budget; block bodies MUST be wrapped in `Label` admin
  instructions carrying the label arity and (for loops) the re-entry
  continuation.
* `w89_eval` MUST return the reference's outcomes: normal completion with
  the resulting value stack, a trap with the reference message
  ("unreachable executed", "integer divide by zero", "integer overflow",
  "invalid conversion to integer"), a crash for ill-typed states
  ("read of uninitialized local", "write to immutable global", "stack
  underflow", "undefined label", "undefined frame"), and (from Phase D on)
  an exception.
* Constants, `nop`, `drop`, `select`/`select_t`, `local.get/set/tee`,
  `global.get/set`, `block`/`loop`/`if`, `br`/`br_if`/`br_table`,
  `return`, `unreachable`, and all numeric test/compare/unary/binary/
  convert instructions MUST execute per the reference semantics, with
  operands taken from the top of the stack in the reference's order.
* `br_table` MUST select `xs[i]` when `i < |xs|` and the default label
  otherwise.
* A `Label` MUST merge its result values (`take n vs0 @ vs`) when a
  `br` reaches depth 0, decrement and re-propagate deeper `br`s, and
  propagate traps/returns/throws outward while discarding the rest of its
  body. A `Loop` label MUST re-enter its body on a depth-0 branch.
* `return` MUST unwind all enclosing labels and deliver the carried
  values to the enclosing frame (crashing "undefined frame" at top level
  in Phase A unit tests).
* Blocktype arity MUST be derived from the blocktype's function type
  index (via the flattened type environment) or from its value type
  (empty = 0, valtype = 1).
* Traps MUST only fire for the specified runtime conditions; the
  reference distinguishes "integer divide by zero" from "integer
  overflow" (INT_MIN / -1).

## MUST NOT

* The evaluator MUST NOT step the rest of a block's body after a
  branching/trapping/returning instruction has been produced; the body
  MUST be discarded.
* The evaluator MUST NOT accept a `global.set` of an immutable global, a
  `local.get` of an unset local, or a `drop`/select/arithmetic on an
  empty stack; each MUST crash rather than produce a value.
* The evaluator MUST NOT evaluate instructions whose phase has not landed
  (calls, memory/table/bulk/ref ops, exception instructions); such
  instructions remain decode/validate-only until their phase.
* The evaluator MUST NOT conflate numeric trap conditions: divide by zero
  and signed overflow MUST produce their distinct reference messages.
* The interpreter MUST NOT be reachable from the CLI before instantiation
  lands (Phase B); `wasm89 load` continues to only decode + validate.
