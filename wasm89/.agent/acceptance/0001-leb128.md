# Acceptance: LEB128 integer decoding

*Specification reference: WebAssembly Core Spec 3.0, section 5.2.2.*

## MUST

* `w89_leb_u32`, `w89_leb_u64`, `w89_leb_s32`, `w89_leb_s64` accept a
  cursor (`const byte **`), a buffer end, and an out-pointer.
* On success the function returns 1, writes the decoded value, and
  advances the cursor exactly past the encoding.
* On failure the function returns 0, writes nothing, and leaves the
  cursor unchanged.
* `u8` values decode within at most 1 byte, `u32` within at most 5 bytes,
  `u64` within at most 10 bytes, `s32` within at most 5 bytes, `s64`
  within at most 10 bytes.
* The canonical spec examples hold:
  * 0xE5 0x8E 0x26 as u32 decodes to 624485;
  * 0x7F as sN decodes to -1;
  * 0xFE 0xFF 0x7F as s16 decodes to -2 (overlong, within bound);
  * 0x83 0x00 as u8 decodes to 3 (overlong, within bound);
  * 0x80 0x80 0x80 0x80 0x78 as s32 decodes to -2^31;
  * 0xFF 0xFF 0xFF 0xFF 0x07 as s32 decodes to 2^31-1.
* A valid encoding may be followed by further bytes; the cursor stops at
  the first terminal byte.

## MUST NOT

* The decoder MUST NOT accept an encoding longer than ceil(N/7) bytes.
* The decoder MUST NOT accept an unsigned encoding whose value has
  non-zero bits at or above position N (e.g. 0x83 0x10 as u8).
* The decoder MUST NOT accept a signed encoding whose bits above N-1 are
  not a sign extension of bit N-1 (e.g. 0x83 0x3E or 0xFF 0x7B as s8,
  0xFF 0xFF 0xFF 0xFF 0x0F as s32).
* The decoder MUST NOT accept a truncated buffer (one that ends before a
  terminal byte).
* The decoder MUST NOT advance the cursor or write a value on failure.
