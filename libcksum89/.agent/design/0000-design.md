# libcksum89 design

## 1. Frozen algorithm parameters

| Algorithm | Width | Poly (normal) | Init | RefIn | RefOut | XorOut | Check("123456789") |
| --- | --- | --- | --- | --- | --- | --- | --- |
| CRC-32/ISO-HDLC | 32 | `0x04c11db7` | `0xffffffff` | yes | yes | `0xffffffff` | `0xcbf43926` |
| CRC-32C | 32 | `0x1edc6f41` | `0xffffffff` | yes | yes | `0xffffffff` | `0xe3069283` |
| CRC-64/NVME | 64 | `0xad93d23594c93659` | `0xffffffffffffffff` | yes | yes | `0xffffffffffffffff` | `0xae8b14860a799888` |
| INET16 | 16 | one's-complement sum | 0 | n/a | n/a | complement | `0xf62a` |

INET16 pairs adjacent octets big-endian, pads a final odd octet with a zero
low byte, folds end-around carry after every addition, and complements the
result.

## 2. Numeric model

- `cksum89_u16` is `unsigned short`; `cksum89_u32` is `unsigned long`.
  They name value domains (`0..0xffff`, `0..0xffffffff`), not object
  widths. C89 guarantees the minimum ranges; a wider `unsigned long` is
  masked or kept naturally inside the domain.
- `cksum89_u64` is `{ cksum89_u32 hi; cksum89_u32 lo; }` with numeric value
  `hi * 2^32 + lo`. The struct is a numeric representation only; it has no
  wire or byte-order semantics.
- No native 64-bit integer operation enters the implementation. Right and
  byte shifts are performed across the limb pair with 32-bit arithmetic.

## 3. Context semantics

- Contexts are public POD value types: no allocation, no ownership, no
  destructor, no hidden pointer. They are copyable by assignment, which
  forks a stream.
- `init` establishes the initial state and works on fresh or reused storage.
- `update` consumes a byte range and is a no-op for `len == 0`
  (`data` may be `NULL`).
- `final` is `const`, derives the externally visible value, and does not
  mutate. A context remains valid for further `update` or `final` calls.
- One-shot functions mean exactly `init; update; final`.

## 4. INET16 streaming state

The context keeps `{ sum, pending, has_pending }`. An update ending between
the two bytes of a word leaves the octet in `pending`; the next update pairs
it with its first octet. Only `final` treats a remaining octet as
`[byte, 0x00]`. The accumulator folds end-around carry after every word so
an arbitrarily long stream cannot overflow.

## 5. CRC implementation model

All three CRCs are reflected. The reflected implementation polynomials are:

| Algorithm | Reflected polynomial |
| --- | --- |
| CRC-32/ISO-HDLC | `0xedb88320` |
| CRC-32C | `0x82f63b78` |
| CRC-64/NVME | `0x9a6c9329ac4bc9b5` (`hi=0x9a6c9329`, `lo=0xac4bc9b5`) |

Production uses conventional byte-at-a-time 256-entry tables:

```text
CRC32:  index = (state ^ byte) & 0xff
        state = (state >> 8) ^ table[index]

CRC64:  index = (state.lo ^ byte) & 0xff
        state = state >> 8 (across the limb pair)
        state = state ^ table[index] (both limbs)
```

CRC64 byte shift across limbs:

```c
new_lo = (lo >> 8) | ((hi & 0xffUL) << 24);
new_hi = hi >> 8;
```

Tables are checked in and declared in `src/cksum89_internal.h` so the test
suite can verify every entry against independently generated Rocksoft
remainders. `tools/gen_tables.py` regenerates the checked-in file; it is not
authoritative.

## 6. Excluded API

Registry, custom polynomials, runtime selector, allocation, allocator
integration, error/status enum, destroy/free, fd/`FILE` helpers,
scatter/gather, combine, RFC-1624 incremental editing, `verify`, hex
formatting, byte serialization, network-order conversion, hardware/SIMD
selection, CPU feature detection, plugins, threads.

## 7. Module boundaries

```text
include/cksum89.h            public contract
src/cksum89_internal.h       GREEN_PURE marker, tables, shared pure helpers
src/cksum89_tables.c         three checked-in 256-entry tables
src/cksum89_crc32_iso_hdlc.c ISO-HDLC context and one-shot
src/cksum89_crc32c.c         CRC-32C context and one-shot
src/cksum89_crc64_nvme.c     two-limb CRC-64 context and one-shot
src/cksum89_inet16.c         pending-byte Internet checksum
```

Shared pure helpers are `cksum89_crc32_step`, `cksum89_crc64_shift8`, and
`cksum89_crc64_xor`. Everything else is translation-unit local. Internal
helpers carry the `GREEN_PURE` marker and are listed in `green.yaml`
`pure_functions`; the public `final` functions are also marked pure because
they derive a value without mutation.

## 8. Build

- `just` is authoritative: `build`, `smoke`, `unit`, `guard`, `cpp-check`,
  `test`, `sanitize`, `matrix`, `tables`, `cmake`, `green`, `check`, `lint`,
  `format`, `doctor`, `clean`.
- `green` reads `build/gcc/compile_commands.json` and
  `build/clang/compile_commands.json`, generated by `scripts/gen_compile_db`
  over `src/*.c` only. Tests never enter the seven-cell matrix.
- `CMakeLists.txt` defines `cksum89` (static, alias `cksum89::cksum89`) and,
  for a top-level configure, `test_cksum89` plus CTest registration.
- `scripts/audit.sh` verifies that no allocation or I/O symbol is
  referenced and that exported symbols are the documented public and
  internal set.
