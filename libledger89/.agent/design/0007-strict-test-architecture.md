# Strict test architecture (v2)

Normative description of the strict suite: layers, protocols, tables,
budgets, and gates. Scenarios are in `.agent/testing/0001-strict-suite.md`;
acceptance criteria are in `.agent/acceptance/0001-strict-suite.md`.

## 1. Layers

| Layer | Artifact | Runs in | Covers |
| --- | --- | --- | --- |
| A1 | Python + ctypes over `build/libledger89.so` | `python3` process | public API tables, state machine, format codecs, adversarial paths, latency, in-process differential |
| A2 | `strictrun` C runner + `faultshim.so` | child process per case | fault injection, crash injection, recovery oracle, differential under faults |
| B | C tables linking `build/libledger89.a` | one process per suite | white-box codecs, scalar helpers, path helpers, model filesystem |

`strictrun` and the shim are test-only; the library never links them.

## 2. ctypes binding rules

- `ledger89_u64` is bound as a `ctypes.Structure` of two `c_uint32` fields
  (`hi`, `lo`) and is passed/returned by value exactly as the ABI does.
- All handles are opaque `c_void_p`; `ledger89_open` receives a pointer to
  one so failures can be observed as NULL.
- `ledger89_slice` is bound as `{c_void_p data; c_size_t size}`; payload
  buffers are `ctypes.create_string_buffer` and stay alive for the call.
- Every wrapper converts a returned `ledger89_u64` with
  `(hi << 32) | lo` and checks the `LEDGER89_*` constants.
- The shared object is built by `just build-shared` from the same sources and
  flags as the archive, adding `-fPIC -shared`.

## 3. `strictrun` protocol

One op per line on stdin; one transcript line per op on stdout.

```text
open <flags-hex> <path>        -> rc=<code>
append <hex-payload>           -> rc=<code> idx=<index>
appendv <hex-payload>,...      -> rc=<code> idx=<index>
appendv_at <rev> <end> <hex>,..-> rc=<code> idx=<index>
append_pattern <seed> <len> <n>-> rc=<code> idx=<index>
sync                           -> rc=<code> stable=<index>
read <index> <capacity>        -> rc=<code> size=<n> data=<hex|crc>
read_meta <index>              -> rc=<code> size=<n>
iter_init <from>               -> rc=<code>
iter_next <capacity>           -> rc=<code> idx=<index> size=<n> data=<hex|crc>
truncate <from>                -> rc=<code>
prune <requested>              -> rc=<code> actual=<index>
rotate                         -> rc=<code>
verify                         -> rc=<code>
state                          -> first=<i> stable=<i> end=<i> rev=<i>
close                          -> rc=0
```

`data=crc:<hex>` hashes payload bytes with CRC-32C so transcripts stay short.
Exit code is 0 when the script completed, 3 when the fault shim fired and the
script could not continue, and 1 on protocol errors.

## 4. Fault shim

`faultshim.so` is loaded with `LD_PRELOAD` for `strictrun` only. It
interposes `open`, `openat`, `pread`, `pwrite`, `fsync`, `fdatasync`,
`ftruncate`, `rename`, `unlink`, `mkdir`, `flock`, `opendir`, `readdir`,
`closedir`, and `close` via `dlsym(RTLD_NEXT, ...)`.

Configuration comes from the environment, read on every call:

| Variable | Meaning |
| --- | --- |
| `LED89_FAULT_OPS` | comma list of op names to match |
| `LED89_FAULT_NTH` | fail/kill the Nth matching call (0 = every call) |
| `LED89_FAULT_ERR` | errno to return (`EIO`, `ENOSPC`, `EDQUOT`, `EFBIG`, `EINTR`) |
| `LED89_FAULT_MODE` | `fail`, `short`, `eintr`, `kill` |
| `LED89_FAULT_ROOT` | absolute path prefix; only matching paths/fds are intercepted |
| `LED89_FAULT_MARK` | file to touch immediately before a kill |
| `LED89_FAULT_COUNT` | file to append the fired op name to |

`short` writes half of a `pwrite` and returns failure (torn write). `kill`
touches the mark file and `_exit(137)`s without running atexit handlers.
`eintr` returns `EINTR` for the configured call and succeeds afterwards.

An fd-to-path table is maintained so fd-based primitives can be filtered to
the case root; fds opened outside the root are never intercepted.

## 5. Crash oracle

For a mutation with pre-state `S0` and post-state `S1`, the permitted
recovered states are `{S0, S1}` refined by the durability contract:

- append: stable prefix of `S1` down to `S0.stable_end`;
- sync: `S0` or `S1` by marker validity;
- truncate/prune/rotate: old topology or new topology, never a mixture.

The oracle is a Python function used by both the shim crash sweep and the
model's crash replay; `strictrun state` plus a full read scan produce the
observed state.

## 6. Table policy

- Every executable case is a row in a module-level table; the row is the
  case name plus its parameters.
- Tables are committed as Python literals generated by
  `test/strict/gen_tables.py` (`just gen-strict-tables`). Regeneration is
  deterministic; the committed output is the source of truth.
- Exhaustive sweeps cover files up to 4 KiB; larger fixtures use per-field
  tables plus seeded sampling. The long tier lifts the caps.
- Seeds are fixed; `LED89_STRICT_SEED` overrides for exploration.

## 7. Budgets

| Limit | Fast | Full | Long |
| --- | --- | --- | --- |
| Case timeout | 20 s | 60 s | 300 s |
| RLIMIT_AS | 512 MiB | 1 GiB | 2 GiB |
| RLIMIT_FSIZE | 64 MiB | 256 MiB | 1 GiB |
| Disk per case | 16 MiB | 64 MiB | 256 MiB |
| Random ops | 2,000 | 200,000 | 2,000,000 |
| Corruption files | <=4 KiB exhaustive | all | all + 10k fuzz |
| Total wall budget | 120 s | 30 min | 8 h |

`SIGXFSZ` is ignored in the driver so RLIMIT_FSIZE produces `EFBIG` instead
of killing the process.

## 8. NLOC definition and ratio gate

`scripts/nloc` counts physical lines that are not blank and not
comment-only. C block comments and `//` lines are removed; Python and shell
lines whose first non-space character is `#` are removed. Source is
`src/*.c src/*.h include/*.h`; tests are every `test/**/*.c`, `test/**/*.h`,
`test/**/*.py`, and `test/**/*.sh`. The gate fails below 10.0.

## 9. Coverage gate

`scripts/coverage` compiles `src/` with `--coverage -O0 -fPIC`, links the
instrumented shared object and runner, runs the fast and full suites against
them, captures with `lcov`, and fails below 95% lines or 90% branches for
`src/`. `LCOV_EXCL_LINE`/`LCOV_EXCL_BR_LINE` may only be used for branches
proven unreachable by a documented probe.

## 10. Tiers

| Recipe | Contents |
| --- | --- |
| `strict-fast` | smoke, API tables, state, format, small corruption, shim self-test, latency smoke |
| `strict` | all fast cases plus full fault/crash matrices, model, adversarial |
| `strict-long` | large fuzz, 2M-op model, exhaustive corruption, latency scaling |
| `strict-sanitize` | runner-based subset against ASan+UBSan |
| `strict-valgrind` | runner-based subset under memcheck |

## 11. Findings and fixes

The strict suite is expected to falsify hypotheses about the library, not to
merely confirm it. The first full run found one contract violation:

- **EINTR was not retried on every primitive.** `.agent/design/0002` section
  6 requires EINTR to be retried transparently. The `fault.*.eintr` rows
  showed EIO from `led89_posix_lock` (open and flock), `led89_posix_sync_dir`
  (open), `led89_posix_entropy` (open), and `led89_posix_list_open`
  (opendir); `readdir` also treated EINTR as end-of-directory. Reproduction:
  `just strict-fast -k eintr` fails before the fix and passes after.
  Fix: `src/ledger89_file.c` retries `open`, `flock`, `opendir`, and
  `readdir` on EINTR and reports readdir errors other than EINTR.
  The fix keeps `just green` passing.

The ratio and coverage gates are verified by `scripts/nloc` (10:1) and
`scripts/coverage` (95% lines / 90% branches over the fast, full, and
white-box suites).
