# V1 public API contract

## Surface

```text
jrpc89_request_new      build request/notification, status + out node
jrpc89_response_decode  decode response into a checked view
jrpc89_id_equal         total structural id comparison
jrpc89_error_code_reserved  reserved interval -32768..-32000
jrpc89_write_frame      NDJSON write (transport)
jrpc89_read_frame       NDJSON read (transport)
```

Everything else is an implementation detail. `jrpc89_has_node` and
`jrpc89_id_present` are internal.

## `jrpc89_request_new`

```c
jrpc89_status jrpc89_request_new(j89_arena *a, const char *method,
                                 j89_len method_len, j89_len params,
                                 const jrpc89_id *id, j89_len *out);
```

Contract:

- `a`, `out`, `id` non-NULL; `method` non-NULL when `method_len != 0`.
- `method` is bytes plus length: embedded NUL bytes are preserved, and a
  zero-length method is allowed. `method == NULL && method_len == 0` is
  treated as the empty method.
- `params == J89_BAD` omits the member; otherwise it must be an array or
  object node.
- `id->kind` must be known; string ids need `str != NULL`; integer ids must
  be exact (`floor(v) == v`, `|v| <= 2^53`).
- The arena must be clean: `j89_failed(a) == 0` and no pending error
  message.
- On failure `*out` is unchanged. `EINVAL` is a bad argument or a libj89
  validation failure; `ENOMEM` is a libj89 allocation failure.

## `jrpc89_response_decode`

```c
jrpc89_status jrpc89_response_decode(j89_arena *a, j89_len node,
                                     jrpc89_response *out);
```

Accepts a response object with `jsonrpc: "2.0"`, exactly one of `result` or
`error`, an error object with integer `code` and string `message`, and an
`id` that is an integer, string, or null. Every other shape is
`JRPC89_EPROTO`.

Postcondition on `JRPC89_OK`:

- `kind == RESULT`: `result != J89_BAD`, `error` zeroed.
- `kind == ERROR`: `result == J89_BAD`, `error.message != NULL`,
  `error.data` is a node or `J89_BAD`.
- `id.kind` is `INT`, `STRING`, or `NULL`.
- String bytes and node indices point into `a` and live as long as `a`.

`*out` is bitwise unchanged on any non-OK return; the implementation builds
a local view and assigns it only at the end.

## Status mapping

| Condition | Status |
| --- | --- |
| NULL `a`/`out`, dirty arena, bad argument | `JRPC89_EINVAL` |
| libj89 allocation failure | `JRPC89_ENOMEM` |
| structurally invalid JSON-RPC message | `JRPC89_EPROTO` |
| transport conditions | `EOF`, `ETOOLONG`, `ETRUNC`, `EIO` |

## Decisions

- `JRPC89_ID_NONE` is the single notification representation; `id` pointers
  are never overloaded with NULL to mean "no id".
- Zero-length methods are allowed; JSON-RPC does not forbid them.
- `rpc.*` method names are not rejected: the specification reserves their
  meaning for protocol extensions rather than forbidding invocation.
- Error codes are `j89_int` throughout; no narrowing to C `int`.
