# libu89 design

## Green source profile (vNext)

Sources conform to the sibling `green` profile: clean as strict C89 AND strict
C23 under GCC and Clang, passing the `green-*` semantic checks and canonical
Allman `clang-format`. Algorithms are written worker/controller: straight-line
computation at a function top level; nested blocks (loop/if bodies) are thin —
a single delegation, binding, prefix update, or terminal return. No
function-like macros; no owned type name ends in `_t`; `NULL` is the null
spelling. `just check` gates this. The green gate currently covers the scalar
core (`u89_version`, `u89_utf8`, `u89_xid`, `u89_width`); `u89_nfc.c` is
conformance-correct (full `NormalizationTest.txt`) but its seven core
algorithm functions are not yet flat-clean and are excluded from the gate —
that rewrite is a scheduled, conformance-revalidated change.

## Naming and layout

- Namespace prefix: `u89_` for public functions and types.
- Public header: `include/u89.h`, self-contained (only `<stddef.h>`).
- Core is alloc-free: callers provide output buffers and lengths.
- Four-space indentation, functional style, most functions 2-3 lines.

## vNext module map

The expanded roadmap adds modules following the acyclic dependency graph:
properties -> normalization/casefold -> UAX #31 -> {UAX #29, UTS #39} -> width /
UTS #55 helpers -> UAX #14 -> wrap. Tables are shared generated data; higher
layers compose lower libu89 primitives rather than reinterpreting Unicode data.

## Module boundaries

| Module | File(s) | Responsibility |
|---|---|---|
| scalar core | `src/u89_utf8.c` | scalar semantics, UTF-8 validate/iterate/encode, positional decode/prev, length-based, byte/codepoint/UTF-16/32 mapping |
| grapheme | `src/u89_grapheme.c` | UAX #29 extended grapheme clusters (GCB, InCB, Extended_Pictographic) |
| properties | `src/u89_props.c` | UCD binary properties, General_Category, East Asian Width, mark/control/emoji classification |
| xid | `src/u89_xid.c` | `XID_Start`/`XID_Continue` predicates |
| width | `src/u89_width.c` | display width, EAW, Unicode-whitespace word wrap |
| normalize | `src/u89_nfc.c` | NFC/NFD/NFKC/NFKD |

Tables are generated by `tools/gen_unicode_tables.py` from the pinned
Unicode 17.0.0 data vendored under `unicode-testdata/17.0.0/`, and committed
as static C89 sorted ranges. `unicode-testdata/17.0.0/SOURCES.txt` records
each consumed file with its sha256, the generator source, and the generation
command (`just tables`); `tools/gen_check.py` re-derives the committed tables
from the vendored data independently (`just gendiff`).

## Scalar semantics

A Unicode scalar value is any code point except the surrogate range
U+D800..U+DFFF. Valid range: U+0000..U+D7FF and U+E000..U+10FFFF.

UTF-8 decoding MUST reject: overlong encodings, UTF-8-encoded surrogates,
code points above U+10FFFF, and truncated sequences. An iterator exposes a
hard-stop error (rejecting) style only; recovery to U+FFFD is deliberately
NOT provided (that is ICU's recovering mode).

## Positional UTF-8 and status

`u89_status` is one enum with `U89_OK == 0` and negative error values
(`U89_EINVAL -1`, `U89_EUTF8 -2`, `U89_ENOSPC -3`, `U89_EWORK -4`,
`U89_EOVERFLOW -5`, `U89_ERANGE -6`); the first five keep the values the
library already used as macros. `u89_utf8_valid` stays the boolean validator
(no status-returning synonym). `u89_utf8_decode(s, n, pos, &cp, &next)`
decodes at an arbitrary scalar boundary and distinguishes end-of-range
(`U89_ERANGE`) from malformed input (`U89_EUTF8`); `u89_utf8_prev` walks back
at most four bytes to the scalar ending at `pos`, and reports `U89_EUTF8`
when `pos` is not a scalar boundary. Both are bounded-time and allocation
free. An internal `decode_one` helper keeps the iterator and the width,
normalization, and casefold callers on the byte-consumed form.

## UTF-16 surrogate primitives

The scalar core owns the UTF-16 mapping facts: `u89_utf16_units` reports 1 or
2 code units for a scalar, `u89_utf16_is_high_surrogate` and
`u89_utf16_is_low_surrogate` classify the surrogate ranges, and
`u89_utf16_decode_pair(high, low, &cp)` maps a valid high/low pair to its
supplementary scalar. The pair operation is a predicate-like `int` (1 on
success, 0 on failure), not a `u89_status`: an invalid pair carries no
operational distinction such as `EUTF8` or `ERANGE`. On failure `*cp` is left
unchanged, and `cp == NULL` performs only the validity test. The library does
not expose a full UTF-16 string decoder; callers that own UTF-16 input can
iterate code units themselves and call the pair primitive.

## Length-based API

All string parameters take `const unsigned char *s, size_t n`. Embedded NUL
(U+0000) is a legal scalar and MUST be preserved. NUL-terminated convenience
variants are provided but never the sole path.

## Disambiguation: width

The width function takes an ambiguity policy enum. `Ambiguous` (EAW "A")
resolves to width 1 (classic wcwidth) or width 2 (CJK-terminal mode) per the
policy. Combining marks, ZWJ/ZWNJ, variation selectors, and ZWSP are width 0.

## Word wrap design note

The wrap primitive breaks only at Unicode whitespace. A whitespace scalar is
never the interior of a grapheme cluster, so word-wrap never splits a cluster
and requires no grapheme iterator and no UAX #14 table. CJK no-space wrapping
is a documented non-goal of v1.
