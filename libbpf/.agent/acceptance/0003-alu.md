# 0003 - Acceptance: ALU/ALU64 arithmetic and byte swap

*Acceptance criteria for the evaluator arithmetic milestone (RFC 9669
sections 4.1, 4.2). Each item is either a behaviour the software MUST exhibit
or a behaviour it MUST reject.*

## MUST

* The register file MUST expose eleven 64-bit registers, initially zero.
* ALU64 ADD/SUB/MUL/OR/AND/XOR MUST compute the wrapped 64-bit result.
* ALU (32-bit) operations MUST compute the wrapped 32-bit result and zero the
  upper 32 bits of the destination.
* Division by zero MUST set the destination to 0 (both ALU and ALU64, signed
  and unsigned).
* 64-bit modulo by zero MUST leave the destination unchanged; 32-bit modulo by
  zero MUST zero the upper 32 bits of the destination.
* Signed modulo MUST use truncated division (`-13 % 3 == -1`).
* ALU64 shifts MUST mask the count by 0x3F; ALU shifts by 0x1F.
* NEG MUST negate the destination.
* MOV K in ALU64 MUST sign-extend the 32-bit immediate to 64 bits; MOV X MUST
  copy the source register.
* MOVSX MUST sign-extend an 8/16/32-bit operand.
* END MUST byte-swap the destination within the selected width (16/32/64);
  ALU END with BE swaps, ALU END with LE is the identity, ALU64 END always
  swaps.

## MUST NOT

* The evaluator MUST NOT perform signed division/modulo that triggers
  undefined behaviour in C (divisor of zero, or `INT_MIN / -1`); such cases
  MUST be handled deterministically.
* A 32-bit operation MUST NOT leave stale bits in the upper 32 bits of the
  destination.
